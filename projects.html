Academic project case studies

Projects focused on analysis, documentation, data organization, and QA review.

These are academic and project-based examples that show how I approach system purpose, business problems, database planning, documentation, and manual review. They are written for entry-level IT Business Analyst, Business Analyst, Systems Analyst, QA Analyst, and Data Analyst roles.

Featured case study

Campus Event Management System

Role
Student systems analyst and documentation contributor
Tools Used
Documentation tools, database planning notes, diagrams, SQL concepts
Problem/Purpose
Campus events need organized records for event details, schedules, participants, approvals, and updates.
What I Did
Outlined the system purpose, identified key users, listed important records, mapped basic event workflows, and prepared documentation to support system development.
Outputs
System overview, database-related notes, feature list, workflow notes, and documentation for event management records.
Skills Demonstrated
Systems analysis, database documentation, requirements thinking, process understanding, and clear written communication.

Business and data analysis

Small Business Challenges Research

Role
Student business/data analysis contributor
Tools Used
Research notes, spreadsheet-style organization, summary documentation
Problem/Purpose
Small businesses face challenges such as limited resources, customer reach, operational issues, and technology adoption.
What I Did
Reviewed gathered information, organized findings by theme, identified repeated issues, and summarized possible improvement areas.
Outputs
Research summary, categorized business challenges, observations, and practical recommendations.
Skills Demonstrated
Business analysis, data organization, research interpretation, summary writing, and problem identification.

CRUD and database documentation

Music Playlist Management System

Role
Student systems/database documentation contributor
Tools Used
Database concepts, CRUD notes, documentation tools
Problem/Purpose
A playlist system needs a clear way to add, view, update, and delete songs while keeping song records organized.
What I Did
Documented the basic CRUD flow, identified important data fields, described user actions, and organized the system logic in a readable format.
Outputs
CRUD documentation, data field list, feature notes, and simple system behavior description.
Skills Demonstrated
Database documentation, systems thinking, data organization, CRUD understanding, and clear technical writing.

QA and product documentation

Mobile App Manual/Revision Documentation

Role
Student QA/product documentation contributor
Tools Used
Mobile app review, manual documentation, revision notes
Problem/Purpose
A mobile application needs clear user guidance and revision documentation so features, changes, and instructions are easier to understand.
What I Did
Reviewed app screens and features, wrote user-facing documentation, recorded revisions, and described changes in a structured way.
Outputs
User manual content, revision documentation, feature descriptions, and QA-style observations.
Skills Demonstrated
QA review, product documentation, attention to detail, user guidance writing, and revision tracking.
