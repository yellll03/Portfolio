Purpose & solution

This academic project models everyday inventory and counter-sale tasks in a desktop interface. It brings item details, stock entry, checkout, and sales records into connected Java Swing windows.

The intended users are Admin and Cashier. The login implementation routes an Admin to the dashboard and a Cashier to the POS screen after matching the selected position and account details.

From item to sale

  1. Maintain the catalogue

    The inventory forms collect item code, name, category, description, price, and quantity. Shared Java lists supply the item table.

  2. Build a cart

    The user selects an item and enters a quantity. The POS screen calculates a line subtotal and updates the displayed totals.

  3. Check the payment

    Cash checkout rejects a non-numeric or insufficient amount and calculates change. Card and split-payment options are simulated locally; no payment processor is connected.

  4. Record the sale

    Checkout generates a receipt and adds dated sale entries with item, quantity, price, payment method, and cashier details. The sales screen reads those entries for its reporting views.

My contribution

I developed inventory and transaction functionality and performed manual functional testing of authentication, stock updates, sales transactions, computations, and report accuracy.

Tech stack

Interface
Java Swing windows and event handlers provide the desktop forms, tables, cart, and dialogs. The project includes NetBeans form files.
Application data
Java collections hold account, inventory, and sales data in memory for this academic prototype.
Receipts & reports
Checkout assembles an HTML receipt and creates Sale objects. The sales window reads the shared sale list.
Java Swing NetBeans

Testing & practical learning

Concrete validation examples

Checkout rejects an empty cart, an invalid total, non-numeric cash, and insufficient cash. Adding to the cart also checks that an item is selected and a quantity has been entered and can be parsed.

I manually tested authentication, inventory updates, transactions, stock calculations, and report accuracy.

What I practiced

I practiced tracing a transaction from input to calculations, receipt output, and sales records. This early project also makes the difference between temporary application state and persistent storage concrete.
